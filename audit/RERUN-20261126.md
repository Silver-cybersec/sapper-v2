## 架构

结论：控制面是事实图加 tmux 编排；执行面是带完整工具链、且默认跳过确认的模型 CLI。权限边界停在提示词，不在进程或容器配置。

- **组件。** `lib/sapper.py` 维护 `.sapper/` 事实图并调用模型 CLI；`lib/arena.py` 用 `BENCHMARK_TOKEN` 访问 `/openapi/v1/challenges`；`lib/kb.py` 只读本地知识库；`docker/entrypoint.sh` 跑 `sapper bench`；tmux / commander 变体由 `docker/Dockerfile.tmux`、`docker/Dockerfile.commander` 与 `docker/commander/{entrypoint,worker,watchdog}.sh` 组成。README 所说的指挥官、士兵、看门狗对应这三套脚本，不是三个独立代码库。
- **数据流。** 平台注入 `BENCHMARK_*`，操作者注入模型密钥。入口探测平台后，`bench` 把题面和靶标地址写入事实图（代码注明为不可信数据），再起 `auto`。探索结果写回图，flag 经 arena 提交。看门狗把轮换后的密钥写入 `$SAPPER_ROOT/rotated.env` 并 `source`。
- **信任边界。** 容器用户是 `agent`（非 root），Dockerfile 未写 `privileged`、`docker.sock`、capability 或只读根文件系统。出网限制、是否挂载宿主，取决于外部平台，本仓没有策略对象。`local-sim.sh` 反而使用 `--network host`。
- **可被绕过的宣称。** README 写指挥官「自己不打」。入口却以 `--dangerously-skip-permissions` 启动指挥官（`docker/commander/entrypoint.sh` 第 105 行）。「只打授权靶标、不外传密钥」写在系统提示（`lib/sapper.py` 第 2919–2927 行）和 hook（`lib/sapper-hook.py` 第 157–162 行），没有第二道强制。`sapper dispatch/auto/bench` 的 `--skip-permissions` 默认关闭，但三套容器入口都会打开它。
- **未覆盖。** 未读完 56 条知识库正文；未对照 README 成绩数字与 `BATTLE-REPORT.md` 做核验。那不是本单启用的功能全表。

## 供应链

结论：直接依赖名和已锁定的 Nuclei 压缩包未见恶意替换；未锁定的安装解析与未拉取的镜像层不能下同样结论。已知漏洞与「是否恶意」分开写。全文在 `audit/supply-chain.md`。

- 无各语言锁文件，无子模块，无 `curl|sh` 安装器。`install.sh` 只做符号链接。
- 基础镜像 `kalilinux/kali-rolling:latest`，无 digest。apt 改到清华 TUNA，包版本不锁定。`@anthropic-ai/claude-code` 不锁定且 `--allow-scripts`；多数 pip 包不锁定；`@openai/codex@0.42.0` 锁了版本、没有完整性校验。
- `docker/nuclei.zip` 的 SHA-256 `725ef892fcffd1b03ad4f0874942fc4b623c0419b6b6c6c91fe4a5a65671f77c` 与 ProjectDiscovery Nuclei **v3.3.7** `nuclei_3.3.7_linux_amd64.zip` 官方校验和一致（发布于 2024-12-02 20:14:59 香港时间，API 原始值 `2024-12-02T12:14:59Z`）。字节一致，但是过期版本，OSV 显示后续 GHSA 影响 3.3.7（含处理不可信模板时的命令执行与读文件）。这不是被掉包，是已知漏洞。
